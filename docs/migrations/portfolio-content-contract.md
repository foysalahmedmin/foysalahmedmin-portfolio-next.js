# Portfolio content contract rollout

This rollout follows expand → backfill → switch → later contract. Project,
Article, and category fields remain optional in the expand release so old records
stay readable while editors complete evidence-backed content.

## Deployment order

1. Deploy the application expand release. Readers accept Mongo ObjectIds,
   canonical slugs, embedded slug history, and alias records. New writes reserve
   aliases transactionally. Public links prefer a slug and legacy identifiers
   issue a permanent page redirect when a canonical slug exists.
2. Run `pnpm db:migrate:dry-run`. Review collision counts and backup/lease
   readiness. Migration `202607150006-content-slug-foundation` normalizes slugs,
   resolves collisions deterministically with an ObjectId-derived suffix,
   backfills aliases/history, and only then creates partial unique indexes.
3. Apply `202607150006-content-slug-foundation`, then
   `202607150007-portfolio-content-contract`. The second migration preserves
   existing Project visibility by mapping legacy `completed` records to the new
   published state, maps only unambiguous delivery states, and derives Article
   word/heading/reading-time metadata from already-sanitized content.
4. Verify ID, canonical slug, and historical slug reads before treating slug
   URLs as the only links generated by public surfaces.
5. In a later contract release, make fields required only after a completeness
   report shows every publishable record has an approved primary pillar and
   honest case-study/editorial data. Do not infer pillars, project type,
   excerpts, roles, outcomes, evidence, or URLs in a migration.

## Operational caveats

- `cancelled` is intentionally not coerced into planned/active/completed. It
  remains readable through the legacy state and requires an editor decision.
- Old current slugs and future renamed slugs remain reserved. Permanent deletion
  does not automatically free an alias, preventing a stale URL from being
  reassigned to unrelated content.
- Only public HTTPS Project links without credentials, local/private hosts, or
  internal host suffixes pass validation. Private/hidden links and outcome
  evidence references are removed from public DTOs.
- Roll back the application before rolling back canonical link generation. The
  migrations are non-destructive; use a new compensating migration instead of
  editing an applied migration file.
