## 4. What the harness and the tests caught

Each of these was a real defect in the first design, found by the new gates and fixed before the phase closed.

1. **A fixed-position pin is a full-screen layout shift.** ScrollTrigger pins by switching the element to `position: fixed`; Chromium reported 0.95 for the pin starting and 0.95 for it ending (layout shift 1.89 in one ten-second probe and 5.6 in the harness's median, against a 0.05 budget). With three pins on Home that would put field CLS far over 0.1. The pinned scene is now CSS `position: sticky` in a track `length` screens taller, with ScrollTrigger only reading progress: layout shift 0.0006 for the same run. The plan already listed sticky as the phone approach; it is now the only approach.
2. **A clip-path wipe never fires.** An IntersectionObserver treats a fully clipped element as not intersecting, so the media wipe (`clip-path: inset(0 0 100% 0)`) could never reveal itself. It is now a cover panel in the page colour that retracts by transform, on a wrapper.
3. **Measuring first-screen blocks during hydration cost 100 ms of blocking time on a throttled phone.** The first reveal applier read `getBoundingClientRect` for every block inside the hydration task, forcing a synchronous layout. Lighthouse (simulated mobile, five-run medians) showed Home TBT 167 to 524 ms and performance 82 to 74. A classifier observer now decides first-screen status after the layout the browser does anyway; with it, TBT and the performance score are back inside the run-to-run spread of Phase 1 (section 5).
4. **Back and forward lost the scroll position under Lenis** (0 after back; without the engine the browser restored only 991 of 1,400 px because the client-rendered page was not tall enough yet). `ScrollRestoration` remembers each page when it is left (wrapping `history.pushState`, which runs before the new page scrolls to the top) and restores it once the page can reach it, with or without smooth scroll.
5. **SplitText's `aria-label` is invalid on a paragraph** (axe `aria-prohibited-attr`), and the line masks would clip tight descenders. Lines are spans, the text stays ordinary text, and the split is reverted when the animation ends, so the end frame is the server markup.
6. **React strict mode (development and CI's dev server) broke two navigation effects.** A "first run" flag made the first page load play the page-enter animation, and a consumed "popping" flag lost the scroll restore. Both are idempotent now; three consecutive CI-style runs on the dev server are green.
7. **Axe judges whatever frame it lands on.** A block mid-reveal has a fraction of its final opacity and reads as insufficient contrast. Specs call `settle(page)` first (three quiet checks in a row); `public-quality.spec.ts` needed it too.
8. **The palette's selected-row hint text was 4.31:1** (`fg-faint` on the raised surface); it uses `fg-secondary`.

## 6. Decisions made while building

- **Touch visitors never get the engine.** The acceptance line says the motion chunk is absent for touch, and plan 3.16 already says no Lenis on touch and pins become stacked sections. So `resolveEnginePolicy` loads GSAP and Lenis only for full motion, a fine pointer and tier 2 or above. Touch keeps CSS reveals, the route shutter where View Transitions exist, the palette and the rail. Phase 5 builds phone pins as sticky plus observer beats.
- **`MotionProvider` stays shared and untouched by the engine.** The engine state lives in `EngineProvider` inside the public surface; the host that loads GSAP is mounted by `PublicSurface`, so the admin's import graph never contains it.
- **Route transition (spike S3 resolved):** a manual `document.startViewTransition` wrapper with capture-phase click handling, not `experimental.viewTransition` (which moves the app to a different React channel for one effect). Feature-detected, 1.5 s safety timeout, CSS page-enter fallback. Back and forward are not wrapped.
- **`@gsap/react` not adopted.** The engine owns plugin registration and every behaviour returns a cleanup that the owning component runs; the extra dependency would add a layer without removing code.
- **The Motion lab is a public-surface route**, `/lab/motion`, not a section of the admin page, because no animation library may be imported from the admin. The System lab's Motion section holds the tokens, the easing curves drawn from the shared functions, the whole registry with build status, and a link. Development serves the lab always; a production build serves it only with `MOTION_LAB=1` (otherwise 404 and `noindex`).
- **One privacy-safe reliability event** (`engine_load_failed`, target and device class only) goes through the existing vitals endpoint with a strict schema and the same switch. It is not one of the C-28 conversion events.
- **The registry is code**, not a document: 46 effects, 11 built (M02, M06, M07, M08, M10, M14, M16, M18, M20, M26, M33), the rest scheduled by phase. `docs/design-system/motion.md` embeds tables generated from it and a unit test fails on drift.
- **`ScrollRestoration` keys pages by path**, so `/projects?page=2` and `/projects` share a position. A hash in the URL is left to the browser.

## 7. Not done in Phase 2 (by design)

- The runtime governor and the WebGL2 and software-renderer probes need the canvas: Phase 3 (the tier resolver already accepts them and may only step down).
- F5 (`content-visibility` for long static sections) arrives with the Home chapters; F12 (3D disposal) with the scene.
- Label roll (M27), nav indicator (M28), header hide and show (M35), theme flip (M21), sheen (M15), footer wordmark (M22), velocity coupling (M23): Phase 3 with the shell and hero.
- A skip link for every pinned scene and the three-pins check on Home: Phase 5 (the engine warns in development past three pins).
- The `smoothness` CI job has not run on GitHub. Real-device feel (mid-range Android, iOS Safari, Firefox, WebKit) is the Phase 9 review.
